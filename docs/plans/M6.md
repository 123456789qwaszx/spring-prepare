## 1. 목표와 한 줄 요약

**Unity 클라가 붙어도 되는 상태.** 비밀번호 해시, 토큰 인증·소유 검증, 관리자 키, 에러 형식 통일, 스키마 결정 마감, README.

끝나면: 토큰 없이 세이브 API → 401, 남의 회차 → 403, DB에 평문 비밀번호 없음, 모든 에러가 같은 형식.

## 3. 숙련자의 사고흐름

1. **Security 전체가 아니라 `spring-security-crypto`만.** 필요한 것은 `BCryptPasswordEncoder` 하나. 전체 Security를 넣으면 필터 체인·CSRF·기본 로그인 페이지가 따라와 학습 범위를 벗어난다. "필요한 최소 의존성" 원칙.
2. **인터셉터 하나로 인증·인가를 다 한다.** `HandlerInterceptor`가 `Authorization: Bearer <token>`을 `sessions`에서 조회 → 만료 확인 → 요청 속성에 `userId`. 경로 패턴은 `/playthroughs/**`, `/users/{id}/**`. 소유 검증(403)은 인터셉터가 아니라 **서비스**에서 (회차의 user_id를 알아야 하므로). 단, `/users/{id}`의 id ≠ 토큰의 userId는 인터셉터에서 바로 403.
3. **토큰은 랜덤 문자열 + DB 행.** JWT는 M6 범위 밖 (PLAN "하지 않는 것"). `sessions(token CHAR(64) PK, user_id, expires_at)`. 토큰은 `SecureRandom` 32바이트 hex. 로그아웃은 행 삭제.
4. **관리자 키는 프로퍼티.** `POST /content/**`는 `X-Admin-Key` 헤더 == `app.admin-key`. 값은 `application-local.properties`. 커밋되는 파일에 기본값을 두지 않는다.
5. **에러 형식은 "누락 케이스 채우기".** M0의 `ErrorResponse`가 이미 있으므로, `@ExceptionHandler(Exception.class)` → 500 통일, `HttpMessageNotReadableException`(JSON 파싱 실패) → 400, `MethodArgumentTypeMismatchException` → 400, 401/403 전용 예외. M4의 409 요약은 `detail`에.
6. **스키마 변경은 마이그레이션으로.** PLAN#4가 (a)면 `V3__event_log_unique_per_playthrough.sql` (기존 UNIQUE 드롭 → 새 UNIQUE). 기존 데이터가 새 UNIQUE를 위반하면 마이그레이션이 실패한다 — 더미 데이터는 지우고 시작.
7. **Flyway를 넣는다면 baseline부터.** 이미 있는 `game` DB에는 `spring.flyway.baseline-on-migrate=true` + `baseline-version=1`, `schema.sql` → `V1__init.sql`로 옮김. `game_test`는 매번 `clean` 후 migrate — 테스트 DB 드리프트 문제(ANALYSIS R4)가 여기서 해소된다.
8. **README는 마지막에.** 실행법·API 목록·마일스톤 상태. `docs/`의 내용을 요약하지 말고 링크한다.

## 5. 특이사항

- **첫 의존성 추가 M.** `spring-security-crypto`, (Flyway). 그 외는 여전히 넣지 않는다.
- **기존 API 호환이 깨진다.** M0~M5의 curl 시나리오는 토큰 없이 동작했다. M6 이후 `M{n}-check.md`는 로그인 단계를 앞에 붙여야 한다 → 각 check 문서 머리에 "M6 이후: 토큰 필요" 주석.
- **Boot 4 Flyway 스타터 이름**: `spring-boot-starter-flyway` (4.0 마이그레이션 가이드: jdbc 스타터가 더 이상 flyway를 자동 포함하지 않음). 추측 금지 원칙대로 릴리스 노트 재확인 후 추가.
- **학습 포인트**: 인증 vs 인가, 해시 vs 암호화, 인터셉터의 위치(DispatcherServlet 뒤, 컨트롤러 앞), 마이그레이션 baseline.

## 7. 완료 기준 체크리스트

- [ ] 토큰 없이 세이브 API → 401. 남의 회차 → 403.
- [ ] `SELECT password FROM users`에 평문 없음 (`$2a$…`).
- [ ] 모든 4xx/5xx가 `{code, message, detail?}`.
- [ ] `X-Admin-Key` 없이 콘텐츠 POST → 401.
- [ ] README에 실행법·API·상태.
