# M8. Unity — 복구와 충돌 UI — 계획서

> PLAN.md §4 M8 기준. 상태: **대기**. 마지막 갱신: 2026-08-28 (초안)
> 작업 장소: Unity 레포. 서버 레포는 문서·(필요 시) 409 본문 조정.

---

## 1. 목표와 한 줄 요약

**새 기기에서 서버 세이브를 내려받아 복구하고, 409 충돌 시 양쪽 요약을 보여주고 사용자가 고르게 한다.**

끝나면: 두 기기(또는 에디터+빌드) 시나리오 — A에서 플레이 → B에서 로그인·복구 → B에서 플레이 → A에서 이어하기 시 409 → 선택 → 끝까지 동작.

## 2. 선행 조건

- [ ] M7 `검증됨`.
- [ ] M4의 409 본문 필드 확정: `revision, updatedAt, device, currentEpisodeId, playSeconds`. UI가 보여줄 것과 일치하는지 확인.

## 3. 숙련자의 사고흐름

1. **복구는 "없을 때만".** 로그인 후 `GET /playthroughs/{pid}/saves` → 로컬에 없는 슬롯만 내려받는다. 로컬에 있으면 로컬이 진실 (M7 원칙). 둘 다 있고 다르면 그것은 충돌이고 다음 PUT에서 409로 드러난다 — 복구 단계에서 병합하지 않는다.
2. **충돌 UI는 정보만 보여준다.** "서버: EP03_02, 12분, iPad, 3시간 전 / 이 기기: EP04_01, 15분". 판단은 사용자. 자동 병합은 PLAN "하지 않는 것".
3. **"서버 것" = GET 후 로컬 교체 + 큐 폐기.** 큐를 버리는 것이 핵심 — 폐기하지 않으면 다음 PUT에서 또 409.
4. **"내 것" = force 재요청.** `?force=true&baseRevision=<서버 revision>`. 서버는 새 이력만 추가 (M4). 이후 revision을 로컬에 저장.
5. **`deviceKey`와 `display_name`.** 충돌 UI가 "어느 기기"를 보여주려면 `devices.display_name`이 채워져야 한다 — M2에서는 `''`였다. M8에서 PUT에 `deviceName`(선택)을 추가할지 → D-0xx. `SystemInfo.deviceName` 정도.
