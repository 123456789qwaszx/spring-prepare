## 3. 숙련자의 사고흐름

1. **"원본 그대로"가 무슨 뜻인지 먼저 정한다.** 바이트 동일인가, 의미 동일인가. MySQL `JSON` 컬럼은 저장 시 공백·키 순서를 정규화하므로 바이트 동일은 불가능하다. 바이트 동일이 필요하면 `LONGTEXT`, 아니면 `JSON`. 이 결정이 M2(스냅샷)·M5(`JSON_EXTRACT`)까지 영향을 준다. → **PLAN#1을 M1 첫 작업에서 결정**.
   - 권장: `JSON` 유지. 근거: (a) 클라(Unity)는 파싱해서 쓰므로 바이트 동일이 필요 없다, (b) M5에서 `JSON_EXTRACT`로 `ChoiceLabel`을 뽑으려면 JSON 타입이어야 인덱스·함수가 자연스럽다, (c) 잘못된 JSON을 DB가 거부해 주는 검증을 공짜로 얻는다. "diff 0"은 **파싱 후 트리 비교**(`JsonNode.equals`)로 확인.
2. **체크섬은 원본 바이트로, 저장은 정규화돼도 된다.** 멱등성 판정 키(`checksum`)는 `@RequestBody String`의 UTF-8 바이트로 계산해 별도 컬럼에 둔다. 그러면 `body`가 정규화돼도 재수입 판정은 흔들리지 않는다.
3. **요청을 `JsonNode`로 받지 않는다.** `@RequestBody JsonNode`로 받으면 Jackson이 파싱→재직렬화하면서 원본이 바뀐다. `String`으로 받아 체크섬을 먼저 계산하고, 그다음 `JsonNode`로 파싱해 색인 필드만 읽는다. (PLAN §2.5 "도메인 객체로 역직렬화 금지"의 실천)
4. **트랜잭션 경계는 Service 메서드 하나.** `importChapter`: 체크섬 조회 → version 계산 → contents INSERT → episodes 배치 INSERT. 하나라도 실패하면 전부 롤백. 롤백 확인은 **일부러 예외를 던지는 코드**가 아니라, **에피소드 ID가 중복된 JSON**을 올려 `chapter_episodes` PK 위반으로 자연스럽게 실패시킨다 — 실제 DB 제약으로 검증하는 편이 학습에 맞고 테스트 전용 코드가 남지 않는다.
5. **배치 INSERT 도구를 여기서 정한다.** PLAN은 M3 "함정"에서 언급하지만 `chapter_episodes` 배치는 M1에서 먼저 필요하다. `JdbcClient`는 배치를 지원하지 않는다 → `NamedParameterJdbcTemplate.batchUpdate(sql, SqlParameterSource[])`. 레포지토리가 `JdbcClient`와 `NamedParameterJdbcTemplate` 둘을 주입받는 것을 허용한다 (이유를 주석으로).
6. **201 vs 200을 응답 코드로 구분한다.** 신규면 201, 이미 있으면 200 + 기존 행. 클라(수입 스크립트)가 "새 버전이 생겼는지"를 상태 코드만으로 알 수 있다.
7. **경쟁 조건은 알고도 무시한다.** version 계산과 INSERT 사이의 경쟁은 `(chapter_id, version)` UNIQUE가 안전망이다 (충돌 시 409). 수입은 개발자 한 명이 수동으로 하므로 락을 걸지 않는다. **알고 무시하는 것과 모르고 지나치는 것은 다르다** — 주석으로 남긴다.

## 5. 특이사항

- **Jackson 3를 처음 만나는 M.** M0 코드에는 Jackson을 직접 쓰는 곳이 없었으므로 여기가 첫 접촉이다. Boot 4.1.1의 `JacksonAutoConfiguration` 소스로 확인한 패키지(2026-08-29):
  ```java
  import tools.jackson.databind.JsonNode;          // com.fasterxml.jackson.databind 아님
  import tools.jackson.databind.ObjectMapper;      // 클래스명은 그대로, 패키지만 바뀜
  import tools.jackson.databind.json.JsonMapper;   // 자동 등록되는 빌더의 결과 타입
  ```
  주입은 `ObjectMapper`로 받으면 된다. 애노테이션(`@JsonProperty`, `@JsonInclude`)만은 예외적으로 `com.fasterxml.jackson.annotation.*` 그대로다 — `common/ErrorResponse`가 이미 그 import를 쓰고 M0에서 동작을 확인했다.
  Jackson 3의 파싱 예외(`JacksonException`)는 **unchecked**라 `@Transactional` 롤백 규칙(RuntimeException만 롤백)에 걸리지 않는다 — 오히려 좋다.
- **`DbCleaner` 확장 순서**: 목록 맨 앞에 `chapter_episodes` → `chapter_contents` → `game_definitions`를 넣는다(기존 `devices`, `users`보다 앞). `chapter_episodes`는 `ON DELETE CASCADE`라 부모만 지워도 되지만, 순서를 명시해 FK 방향을 눈에 보이게 두는 편이 낫다.
- **두 개의 JDBC 진입점.** `JdbcClient`(단건)와 `NamedParameterJdbcTemplate`(배치)가 같은 레포지토리에 공존한다. 둘 다 같은 DataSource·같은 트랜잭션을 탄다 (`DataSourceUtils`가 스레드에 바인딩된 커넥션을 준다) — 그래서 배치가 같은 트랜잭션 안에서 롤백된다.
- **읽기 API는 원본 JSON을 문자열로 통과시킨다.** 서버는 `body`를 파싱하지 않는다. `String`을 `@RestController`에서 그대로 반환하면 `text/plain`이 될 수 있으므로 `ResponseEntity`에 `Content-Type: application/json`을 명시한다.
- **학습 포인트**: 트랜잭션 롤백을 "믿는" 것과 "보는" 것의 차이. 테스트에서 실패 후 `SELECT COUNT(*)`로 두 테이블 모두 0임을 확인한다.

## 6. 주의사항 (증상 → 원인 → 대응)

| # | 증상 | 원인 | 대응 |
|---|---|---|---|
| C1 | GET 본문이 올린 파일과 공백·키 순서가 다르다 | MySQL JSON 정규화 | 정상(PLAN#1=JSON일 때). 비교는 `JsonNode` 트리 비교 |
| C2 | 같은 파일 재POST가 201 | 체크섬을 재직렬화된 문자열로 계산 | `@RequestBody String`의 바이트로 계산하는지 확인. 클라(curl)가 줄바꿈을 바꾸면 다른 파일로 본다 — 이것도 정상 |
| C3 | INSERT가 `Invalid JSON text` (MySQL 3140) | 잘못된 JSON을 JSON 컬럼에 넣음 | 서비스에서 `JsonNode` 파싱을 INSERT 전에 하므로 400으로 먼저 걸러진다. 그래도 나면 파싱과 INSERT 사이에 문자열이 바뀐 것 |
| C4 | 롤백 테스트에서 `chapter_contents`만 남는다 | `@Transactional`이 안 걸림 — 같은 클래스 내부 호출(self-invocation), 또는 private 메서드, 또는 checked 예외 | 컨트롤러→서비스 공개 메서드 호출인지 확인. 예외가 RuntimeException 계열인지 확인 |
| C5 | 배치 INSERT가 한 건씩 나간다 (느림) | MySQL Connector/J는 기본적으로 배치를 개별 문장으로 보냄 | 학습 규모에선 무시. 필요하면 URL에 `rewriteBatchedStatements=true` (M5 EXPLAIN 때 같이) |
| C6 | `version`이 2가 아니라 1로 또 들어가 409 | MAX(version) 조회와 INSERT 사이 경쟁, 또는 chapter_id 오타 | 수동 수입에선 발생 안 함. 409면 그냥 재시도 |
| C7 | `Nodes[].NextOptions`가 없는 노드에서 NPE | JSON에 키가 없음 (`path()` vs `get()`) | Jackson `path("NextOptions").size()`는 missing node에서 0. `get()`은 null 반환 |
| C8 | `display_name`이 100자 초과 → 400 | DDL `VARCHAR(100)` | 정상. VnTool 쪽 제한과 맞출지 M7에서 확인 |
| C9 | `GET /content/chapters/{chapterId}/latest`가 `/{version}`과 충돌 | 경로 변수 `{version}`이 "latest"를 삼킴 | `latest`를 먼저 선언하거나 `{version:\\d+}` 정규식 제약 |
