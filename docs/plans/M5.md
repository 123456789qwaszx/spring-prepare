## 3. 숙련자의 사고흐름

1. **SQL을 파일로 뺀다.** M5 쿼리는 길고, Workbench에서 그대로 실행해 보는 것이 목적이다. `src/main/resources/sql/stats/*.sql`을 레포지토리가 클래스패스에서 읽는다 (`ClassPathResource` + `readString`). 앱 SQL과 Workbench SQL이 **같은 파일**이라는 것이 요점.
2. **집계는 먼저 SQL로 맞춘 뒤 앱에 붙인다.** Workbench에서 숫자가 맞을 때까지 쿼리를 다듬고, 앱은 그것을 실행해 DTO로 옮길 뿐. 앱에서 루프로 세는 순간 DB를 쓰는 의미가 없다.
3. **비율의 분모를 명확히.** "EventKey 도달률 = 도달 회차 수 / 전체 회차 수"에서 전체 회차는 종료된 회차인가 전부인가? "선택 비율 = 옵션 선택 수 / 그 에피소드에서의 총 선택 수"에서 버전을 나눌 것인가? 이 정의를 쿼리 주석 첫 줄에 쓴다. 숫자가 틀린 대부분의 원인은 SQL이 아니라 정의다.
4. **`JSON_EXTRACT`는 표시용.** `ChoiceLabel`을 `chapter_contents.body`에서 뽑는 것은 "해석"이 아니라 라벨 조회다. 경로 `$.Nodes[?]`는 MySQL JSON path가 필터를 지원하지 않으므로 `JSON_TABLE`로 Nodes를 행으로 펼친 뒤 `episode_id`로 JOIN한다 — 이것이 M5에서 가장 어려운 SQL이다. 안 되면 앱에서 `JsonNode`로 라벨만 붙이는 대안(허용 범위: 해석 아님).
5. **EXPLAIN은 "전"을 먼저 기록한다.** 인덱스를 추가하기 전 `type=ALL`(full scan), `rows`를 적고, 인덱스 추가 후 `type=ref/range`, `rows` 감소를 적는다. 더미 200행에서는 시간 차이가 없다 — **rows 수와 type의 변화**를 보는 것이다. 인덱스 추가는 `db/migrations/V2__stats_indexes.sql`.
6. **인덱스는 쿼리가 요구할 때만.** `event_log(event_key)`는 이미 있다. `choice_history(chapter_content_id, episode_id, option_index)`, `save_slots(updated_at)` 등은 EXPLAIN이 full scan을 보여줄 때 추가한다. 미리 넣지 않는다.

## 5. 특이사항

- **첫 마이그레이션 파일**이 나온다 (`db/migrations/V2__stats_indexes.sql`). Flyway 없이 수동 적용하되 형식은 Flyway 규약으로 — M6에서 Flyway를 넣으면 그대로 baseline 뒤에 붙는다.
- **`JSON_TABLE`**: MySQL 8.0.4+. `JSON_TABLE(body, '$.Nodes[*]' COLUMNS (episode_id VARCHAR(50) PATH '$.EpisodeId', options JSON PATH '$.NextOptions'))` → 다시 `JSON_TABLE(options, '$[*]' COLUMNS (idx FOR ORDINALITY, label VARCHAR(200) PATH '$.ChoiceLabel'))`. 중첩 두 번. `option_index`는 0-based, `FOR ORDINALITY`는 1-based → `idx - 1`.
- **학습 포인트**: GROUP BY와 분모 정의, JSON_TABLE, EXPLAIN 읽기(type, key, rows, Extra), 복합 인덱스의 컬럼 순서.

## 7-1. M5에서 확인된 사실

M4 §7-1의 F30~F33에 이어지는 번호다.

| # | 사실 | 근거 | 어디에 쓰이나 |
|---|---|---|---|
| F34 | **세션 변수는 커넥션에 붙어 있고 풀은 그것을 되돌리지 않는다.** seed 끝의 `SET SQL_SAFE_UPDATES = 1` 이 무관한 테스트 6건을 오류 1175 로 죽였다 | 실행 검증 §7 | M6·M9 에서 스크립트가 세션 상태를 건드릴 때. **"원상복구" 는 원래 값을 알 때만 옳다** |
| F35 | **`@SqlConfig` 의 encoding 기본값은 플랫폼 기본**(한국어 Windows = MS949)이다. UTF-8 스크립트가 깨져 들어가는데 **SQL 문법도 행 수도 멀쩡하다** | 실행 검증 §7 | M6 Flyway 도 같은 함정이 있다 (`spring.flyway.encoding`) |
| F36 | **인덱스를 추가해도 `rows` 는 안 줄 수 있다.** 200 → 200 인데 `type` 이 `ALL → ref`, `Using temporary` 가 사라졌다 | M5-explain §2 | M9 성능 비교에서 무엇을 재야 하는가 |
| F37 | **인덱스가 있어도 옵티마이저가 안 쓸 수 있다.** 전(前) 의 `choice_history` 가 그랬다 — 200행 전부가 대상이라 인덱스를 타는 비용이 더 컸다. 커버링이 되자 판단이 뒤집혔다 | M5-explain §2 | 인덱스를 넣고 **반드시 EXPLAIN 으로 확인**한다 |
| F38 | **제약이 인덱스가 된다.** `user_summary` 가 쓰는 인덱스 셋이 전부 PK·FK·UNIQUE 이고, 조회를 노리고 만든 것이 하나도 없다 | M5-explain §3 | M6·M9. 인덱스를 더하기 전에 **이미 있는 제약이 하는 일**부터 본다 |
